# 升级实施记录

## 2026-09-05：第一批——执行与验收可靠性

这批改动先修复审查中可复现的状态、持久化和放行问题，保留现有前端、工作流类型和 SQLite。它是升级计划的第一批实现，不表示完整的隔离交付链或四阶段改造已完成。

### 已实现

- SQLite schema v2：持久化节点角色、输入、契约、准入/准出条件及审核元数据，并保存 Turn 的工具调用和文件修改数，保留合法的零 token 用量。有历史 Run 数据的磁盘数据库会先通过 `VACUUM INTO` 生成一致性备份，再在事务中迁移；备份或迁移失败则停止初始化。旧版本已经丢失的契约不能凭空恢复，相关节点标记为需要人工审核，禁止自动放行。
- DAG：条件未知时等待；明确匹配 failed 的边可进入恢复节点；入口节点也检查准入条件。不支持的准入/准出表达式不再默认通过。
- 验证：移除默认检查命令中的 `|| true`；脚本改为异步执行；检查失败、缺少目录、验证禁用/异常均不能被当成通过。代码节点从所属项目解析实际验证目录，并校验符号链接后的边界。
- 验证证据：绑定 Turn、验证配置、工作目录、Git HEAD、跟踪文件 diff 和非忽略未跟踪文件内容。代码或配置变化、开始新 Turn 时，旧结果失效。验证过程修改代码也需要重新验证。
- 完成门禁：自动审批、DET/HYB 成功结果、手动批准和 API 提交完成统一经过完成检查。冷启动使用显式阻断，置信分限制在 0–100；分数不能抵消必需检查失败。
- 调度：ready/running 持久化状态作为待执行队列，每个 Run 串行领取执行名额；领取发生在异步准备前，结束后补位。自动执行按 LLM/DET/HYB 模式分派；手动领取同样受 maxParallel 约束。同一个节点不能同时启动多个 Turn。
- 重启：丢失进程的节点进入 failed，Run 暂停，防止未确认外部副作用时直接重放任务。
- 进程：避免 error/close 重复结束同一个 Turn；取消 HYB 后不再启动 LLM fallback。
- 部分安全加固：Git diff 的 ref 经参数数组解析为 commit，不再拼进 shell；clone 使用参数数组；Codex 默认使用 workspace-write；主要执行子进程使用环境变量白名单，避免继承服务端和 OAuth 凭据。CORS 预检移到 API token 校验之前。
- CI：新增 PR/main 的 lint、build、test 工作流。A2A 测试使用内存数据库，避免测试触发个人数据库迁移。

### 行为变化与当前边界

- 过去只根据输出文本判断 lint/test 通过，现在必须实际运行检查。配置检查命令应返回真实退出码，避免人为使用 `|| true` 隐藏失败。

## 2026-09-06：第二批——隔离执行、代码快照与交付闭环

### 已实现

- 正常应用启动时，为 AgentService 注入工作区服务。LLM、DET、HYB 三个执行入口均先建立独立 worktree，再启动进程；HYB fallback 和打回重试建立新的 worktree，继承前一次尝试的修改。
- 新增本机执行账本 `~/.agent-flow/workspaces/execution/`：保存 Run 基线、Turn 的仓库、分支、工作目录、输入与产出 commit。JSON 通过临时文件原子替换，读取时校验 worktree 路径、Git common directory、分支和目录边界。此账本不进入远程工作流同步。重启后可按 Turn 恢复工作区并重新生成 Diff Review。
- 第一次执行要求所属仓库已提交且有当前分支；不会自动提交、清理或暂存用户项目中的修改。Run 固定初始 HEAD。普通后继从已完成前驱的快照出发，多前驱在新 worktree 内合并；冲突保留现场并明确失败。失败分支只传递失败上下文，不继承未经批准的失败代码。
- 进程结束时先在专属 worktree 提交代码快照，再进入验证。Git 快照禁用本地 hooks 和提交签名，使用参数数组及 AgentFlow 提交身份；要求所有输入前驱仍在产出历史中。未解决的冲突或丢失前驱历史不能作为成功产出。
- 验证严格定位到最新 Turn 的 worktree 和 `scriptCwd`；快照不存在、HEAD 变化或工作区变脏时拒绝验证/放行。代码指纹覆盖整个仓库，修复从子目录验证时遗漏仓库其他位置未跟踪文件的问题。
- Diff Review 只读取已完成代码快照，不再通过“打开审查”触发 Git add/commit。Review 的基线是整个 Run 的初始版本，因此后继审查包含前驱产出，适合在最终节点统一交付。
- 本地合并和 PR 入口要求：节点已批准、当前最新 Turn、验证仍然有效、产出 HEAD 与审查一致。合并要求原项目干净且仍停留在 Run 的基线；分支推进后需在新 Run 中集成并重新验证。移除错误方向的 rebase 合入路径。PR 推送固定 commit，取消自动强推重试。
- 关闭审查保留分支和工作区，供重试/下游使用。前端改为“合入已批准代码”，未批准时按钮禁用，展示后端拒绝原因；移除 rebase 选项。重启后节点的 GET review 接口可从账本重新生成审查。
- 旧版 worktree 挂载失败不再降级到 symlink。旧对抗审查通过主 Turn 递归执行，会破坏隔离链路，因此在新执行模式下明确阻断；改用普通 review 节点。
- 可选 LLM reviewer 使用同一工作目录和提供方环境白名单，改用参数数组，不再在服务目录执行 shell fallback。Codex 使用 read-only，Claude 禁用内置工具；这仍是旧 CLI reviewer，不等于完整 provider adapter。Claude 参数参考[官方 CLI 文档](https://code.claude.com/docs/en/cli-usage)。

### 验证结果

- 前后端 `yarn build` 通过，最终后端类型检查通过。
- 后端完整回归：17 个测试文件、176 项通过；新增的 11 项隔离/交付回归在最后的前驱历史检查调整后再次运行。
- 真实临时 Git 仓库覆盖：并行隔离、多前驱合并、冲突保留、重启读取、失败修改继承、项目原有修改与索引保护、只读审查、批准门禁、过期 HEAD、目标分支推进、准确合入、嵌套验证目录。
- 真实脚本端到端覆盖 DET → 验证 → 打回重试 → 批准 → 后继继承 → 最终合入；本地假 CLI 覆盖 LLM spawn 和 HYB 失败后的 LLM fallback。没有调用真实模型或远端 GitHub。
- Lint 0 errors，仍有原来的 7 个 React Hooks warnings；`git diff --check` 通过。

### 使用方式与边界

1. 在项目原仓库提交本次任务需要的代码。新 Run 从这次提交出发；项目目录可以是仓库中的子目录。
2. 用相对项目路径配置 `scriptCwd`。工作区路径和起始 commit 会显示在 Turn 输出中。
3. 需要的依赖应在 worktree 中准备：被 Git 忽略的 `node_modules`、构建缓存和本地环境文件不会自动复制。可以配置独立的准备节点或在任务脚本中显式执行安装步骤；安装会使用项目所配置的脚本权限。
4. 审查、批准节点后再交付。建议完成整个链路后从最终节点统一合入；提前合入中间节点会改变目标基线，使后续本地合入需要重新集成和验证。
5. 重启后工作区可恢复，验证证据仍要求重新运行。旧任务若没有本地执行账本，需要创建新 Run，不能将共享目录里的历史修改冒充为已隔离产出。

当前只支持本地、已有提交的单 Git 仓库，submodule 项目明确拒绝；多仓库、依赖自动准备、受控清理/磁盘配额尚未实现。Git worktree 只隔离文件副本，不隔离系统进程、共享 Git 配置、网络或外部副作用。DET/HYB 仍需可信脚本，子进程组终止和 OS sandbox 留待后续。账本和 SQLite 是独立持久化，崩溃窗口以明确失败、保留现场处理，不宣称分布式事务或 exactly-once。Git 工作区准备/快照仍采用有超时的同步调用，大仓库可能暂时阻塞事件循环，后续应迁入独立执行 worker。

下一步优先实施 provider adapter、结构化事件与 session 恢复，以及执行 worker；随后处理多设备 tombstone、依赖环境记录和可控清理。尚未提交或推送本项目的 Git 改动。

## 2026-09-06：第三批——Provider 结构化协议与显式会话恢复

### 已实现

- 新增 `services/providers/adapter.ts`，集中构建 Codex / Claude CLI 参数并将 JSONL 事件转换成统一的 session、text、tool、file、usage、completed 和 diagnostic 事件。Codex 使用 `exec --json`，Claude 使用 `--print --output-format stream-json --verbose`，移除旧的 `--no-input`。Prompt 通过 stdin 发送；自定义 CLI 保留既有文本模式。
- 成功条件同时要求进程正常退出、没有取消/超时/传输错误、收到 session 和明确的成功终止事件，以及工作区快照成功。缺少终止事件、JSON 损坏、会话变化、重复终止事件、provider 报告失败或 Claude 权限拒绝均不能放行。
- JSONL 解码支持分块和跨 Buffer 的 UTF-8 字符；每条事件最多 1 MiB、原始协议流最多 32 MiB、最多 10,000 条协议记录。未知事件允许前向兼容；工具输入和 reasoning 不复制进任务输出。stderr 仅作诊断，不能参与产出物/用量解析。
- Codex / Claude 使用结构化用量，缺失时保持未知；不再从这两家的自然语言输出估算 token。Codex 输入含缓存命中计数，不重复累加；Claude 将 input、cache read、cache creation 合计为输入量。自定义文本 CLI 暂保留原有兼容解析。
- 本机工作区账本新增 provider 元数据和带单调 sequence 的事件 JSONL。会话 ID 到达后立即写入本机元数据及 Turn 的 SQLite metadata；保存 provider、命令、模型、cwd 和进程 PID，供恢复校验。日志不进入工作流远程同步。写入失败或事件解析失败会使该次执行失败。
- 新增 `POST /api/agents/resume-turn`，请求体为 `runId/nodeId/turnId/prompt`。只能显式恢复当前节点最近一次失败的 provider Turn；必须先恢复处于 paused 的 Run。恢复前核对本机账本、工作区所属关系、项目目录、provider 配置及旧 PID；没有本机账本、配置变化、旧进程可能存活或并发重复恢复都会被阻断。不会用 `--last` 或根据远程传来的会话 ID 选择本机会话。
- 恢复会话产生新的业务 Turn，并继续使用原隔离 cwd，保持 provider 历史工具路径一致。旧尝试先保存代码快照，新尝试重新记录产出并走原有验证/批准门禁。常规打回重试仍创建新 worktree；“恢复会话”与“重新执行”行为明确区分。
- 失败节点新增“恢复上次会话”按钮。新增 `GET /api/agents/events/:runId/:nodeId/:turnId?after=<sequence>`，返回 `events/nextCursor/hasMore`，每页最多 200 条；校验 Turn 所属关系和游标，可在断线后按游标读取已持久化的事件。此接口尚未接入现有 WebSocket 的自动断线补发。
- CLI 可用性检查改用参数数组调用 `which`，移除 shell 拼接。为显式传入测试数据库路径的 RunManager 禁用个人旧 JSON 数据迁移，重启测试不读取个人任务数据。

### 协议依据

已查阅当前官方页面，并用本机 `codex exec --help`、`codex exec resume --help` 和 `claude --help` 检查已安装 CLI 的参数。只运行了帮助命令，没有发起真实模型请求。

Codex 的 sandbox 选项放在父级 `exec` 命令上，再追加 `resume <sessionId> -`；不使用越权模式或失败后静默降级。Claude 按现有权限配置执行，权限不足时明确失败。

### 当前边界与下一步

这批使用结构化 CLI adapter，尚未迁移到 Codex App Server / Claude Agent SDK 长驻客户端。事件日志可按游标读取，但不是完整事件溯源系统；没有跨设备 session 复制、自动进程重放或 exactly-once 保证。恢复仍依赖提供方保存在本机的会话文件；这些文件被清理后，恢复会明确失败，需要重新执行。

## 2026-09-06：第四批——独立执行 Worker、进程组与实时重连

### 已实现

- 新增独立 Node 子进程 worker。主 AgentService 负责领取节点、创建 Turn、接收输出和调用验证/审批；worker 负责工作区准备、主任务 CLI/DET 脚本、provider JSONL 解析、本机 provider 日志、进程终止和最终代码快照。LLM、DET、HYB 共用执行入口，移除原来重复的进程生命周期实现。
- Worker 准备好工作区后，必须通过主服务的第二次执行授权才可启动 CLI。准备期间取消、暂停 Run 或节点状态变化，均不能绕过这一检查。创建任务立即返回 Turn ID，工作区中的同步 Git 操作不会阻塞主服务事件循环。
- Worker 使用单独的 IPC 通道。命令环境沿用白名单和显式 agent.env；worker 自身不继承完整服务环境。开发/测试使用 tsx 启动 TS worker，生产构建直接运行 JS worker。工作输出最多 32 MiB，IPC 待发送队列有上限，超限明确失败。
- POSIX 上每个执行进程建立独立进程组。取消/超时先对整个组发送 SIGTERM，再对未结束的组发送 SIGKILL；父进程退出后仍运行的普通子进程也会清理，且不会被当成成功交付。停止过程完成后才捕获代码快照。
- Worker 检测主服务 IPC 断开并停止任务；主服务设置取消宽限期和整体超时监控，在 worker 无响应或提前退出时终止已知执行组并将 Turn 标记失败。普通脚本失败且快照正常才允许 HYB fallback；取消、超时、worker/协议失败不再自动启动另一轮模型执行。
- 服务正常退出时，先停止领取新执行并取消已有 worker，再等待结果及持久化。强制结束 worker 的异常路径保留工作区，禁止将缺少快照的结果当作成功。
- 为多 worker 并行准备增加原子 Run 基线发布：完整临时文件通过原子创建链接发布，同一个 Run 只有一份初始基线；已有账本更新使用唯一临时文件，避免并行操作覆盖同一个 `.tmp`。
- 新增 RealtimeReplay：所有工作流广播带 server epoch 和单调 sequence，保留最多 2,000 条、8 MiB 的重放窗口。客户端连上后发送 `sync:request`，服务端先补发缺失事件；游标过期、未来游标或服务器重启时，改发完整的 runs/activeTurns 状态快照，再发送 `sync:ready`。
